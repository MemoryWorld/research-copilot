# 实验设计与证据边界

## 已运行的验收口径

`pytest` 使用网络守卫、真实临时 SQLite 和实际文本 PDF；Qwen 为 mock HTTP 契约或显式假客户端。测试能够证明解析来源、持久读写、排序流程、校验分支、工具约束和恢复行为，不证明真实 Qwen 能力。

`python -m research_copilot.evaluation` 的 6 个固定合成验收：有依据回答与原文引用、多轮指代、未知知识拒答、算术工具、重建持久化、trace 落库。每个案例输出通过/失败条件。它不是独立泛化评测集，也没有“提升 X%”之类结论。

## 有模型资源后再做的效果实验

1. **数据集：** 使用可公开且许可清晰的技术文档，按文档族分 tuning/test；人工编写事实问答、跨段组合、无答案、指代和恶意指令案例。标注证据 chunk、允许答案、必须拒答原因。不把测试问答写进知识库。
2. **消融：** BM25、dense、RRF、RRF+词面重排、RRF+Qwen 重排；相同 chunk、top-k、模型、温度与调用预算。调优集确定阈值后冻结，测试集只运行最终配置。
3. **检索：** Recall@4、MRR、来源命中率、各阶段 p50/p95 延迟。人工标签是基准；字面命中只作诊断。
4. **答案：** 人工判定事实支持率、引用完整性、答案覆盖度；无答案集的拒答 precision/recall。将“原文匹配通过”和“答案事实正确”分别计数。
5. **Agent：** 允许/禁止工具选择、参数合法率、达到目标比例、超预算比例、重复调用；指代多轮和会话隔离分别统计。
6. **效率：** 全部 chat、embedding 和 rerank 的真实 usage 与实际账单口径；逐阶段耗时、峰值内存、每百问成本。当前 trace 的 chat usage 不足以计算总成本。
7. **可复现：** 保存数据版本、模型准确 ID、API 区域、参数、代码提交、逐题 trace 和失败案例；报告样本数、置信区间与失败分布，不只挑选截图。
