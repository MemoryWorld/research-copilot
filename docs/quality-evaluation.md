# 检索与问答评测

冻结数据位于 `src/research_copilot/benchmark_cases.json`，版本 `synthetic-rag-v1`。8 份人工编写的演示资料、12 个问题；10 个有答案问题中有一题需要两份资料，另外两题没有答案。问题和标签不会传给检索器；只有问题文本进入检索。数据开发者与实现者相同，不能称为独立盲测，也没有以此调优后的泛化结论。

## 运行与产物

`python -m research_copilot.benchmark --output .data/quality-benchmark.json` 使用临时数据库，结束时关闭连接并清理；不会读取或改动浏览器演示库。报告带数据文件 SHA-256、模型/embedding 指纹、变体、逐题返回文档、标注与耗时。所有错误保留，报告只保存错误类别，不写供应商响应或凭证。

四个变体复用同一个检索实现，只切换召回策略和重排开关。BM25 查询阶段不计算 embedding；dense 使用当前配置的编码器，离线默认是特征哈希。RRF 使用 k=60。评测以文档为单位去重再取前三，避免同一文档多个切片重复得分。生产问答仍默认调用混合检索加重排。

## 指标定义

- Recall@3：前三个唯一文档命中相关文档的比例，多资料问题分母为相关文档总数。
- MRR@3：前三名中第一个相关文档排名的倒数，未命中记零。
- nDCG@3：相关/不相关二元标签，按位置折扣并用理想排列归一化。
- 标注词覆盖：回答未拒答且包含该题全部标注词；不是语义正确率，也不接受它替代人工事实核对。
- 有答案非拒答、无答案拒答：分别保留各自分子分母。请求错误都不算成功。
- 回答的来源完整性：非拒答输出中的 ID、原文引文与编号通过已有校验；不判断语义蕴含关系。
- 耗时：本次端到端调用的墙钟时间。小样本、无标准化负载，不能当生产性能承诺。供应商 usage 仅覆盖回答调用，不是全链路成本。

## 2026-09-23 离线结果

[完整报告](evidence/quality-offline-20260923.json) 是实际运行产物。四种检索配置在这组简单语料上的 Recall@3、MRR@3、nDCG@3 均为 1.0，因此无法证明任何配置更强。

回答标注词覆盖为 9/10，有答案非拒答为 10/10，无答案拒答为 1/2，已回答输出的来源完整性为 11/11。多文档问题 q10 的离线回答只摘录一份文档；q12 询问资料未说明的董事长信息，却因公司名重合召回了相关文档并摘录。这两个失败真实保留。前者需要多证据综合生成，后者需要答案可回答性判断，仅凭召回相关度或引文存在不足以解决。

## 真实模式

配置 `COPILOT_MODE=qwen`、官方端点和本机环境密钥，按 README 显式执行 `--mode qwen --allow-provider-calls`。此时向量和回答使用真实服务；把模型、区域、重排方式与数据哈希一起冻结后，再与基线比较。当前没有真实 Qwen 结果，不给出效果提升或成本结论。进一步评测应添加来自真实任务且可共享的授权数据、人工答案标注、同义改写与无答案难例，并按来源划分开发/最终评测集合。
